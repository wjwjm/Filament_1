## 先回答五个问题

1. **巨大差距仍存在，但应区分时钟范围。** 原尺寸应用、八区间完整传播窗口、第2–8区间的 CPU/GPU OFF 中位耗时比分别为 **7.014、28.815、34.976**。小网格分别为2.104、4.600、4.291。历史“约27倍”来自CPU入口POST节奏与GPU长前缀中选定screen吞吐率的混合，不能作为本次硬件倍率；本次窗口结果接近它不是对历史口径的追认。
2. **差距主要在持续传播，而非窗口外启动。** 原尺寸三次OFF独立均值的应用差为295.088秒。其中第2–8区间贡献248.784秒（84.31%），首区间及窗口内其余工作贡献41.462秒（14.05%），窗口外贡献4.843秒（1.64%）。这是三个互斥完成墙钟范围；原尺寸逐算子CPU−GPU差仍为UNKNOWN。
3. **CPU并行覆盖不足以填满96核，但原因不能单凭占用判断。** 原尺寸OFF窗口的process_cpu/wall约3.17–3.20，第2–8区间约3.23–3.25。CPU有效LIGHT中Raman/Heun约106.92秒，是最大已命名类；管理及未分配余项41.04秒、电离39.15秒。GPU主机8核的OFF窗口占用当量约0.36–0.63；没有设备kernel活动轨迹，不能断定它已算力或带宽饱和。
4. **实测支持工作量匹配、持续段差距和CPU热点；具体硬件瓶颈未证实。** 两端冻结输入、complex128、物理开关、z日程及正常输出一致；同后端透明性规则保留。GPU原尺寸LIGHT/OFF的应用、窗口、later配对比中位为1.133、1.507、1.669，原门失败。保留全部OFF，不把异步host时间与CPU完成时间混减，不以AUX或历史样本替补。
5. **唯一下一CPU方向：稳定场能量诊断的表达式临时物化。** 只评审C3私有Raman namespace的`stable_field_fluence_and_loss`，先核验并复用现有O1 `stable_expression`点表达式路线，保留原NumPy归约。该叶每窗16次、有效LIGHT中位24.739秒；若局部达到2倍/4倍，零新增成本情景仅支持窗口约1.043/1.066倍、应用约1.038/1.058倍。没有实施或新作业授权，详见[NEXT_CPU_OPTIMIZATION_CONTRACT.md](NEXT_CPU_OPTIMIZATION_CONTRACT.md)。

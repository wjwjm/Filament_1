# CPU-S4-6C 事前固定计划

默认 I0；参考 L1；所有结果停于 MANUAL_REVIEW_PENDING。本目录属于独立研究分支，不写 S4-6B 状态或生产代码。

## 输入与调用范围

复用 CPU 8855018 资格时保存的首个 pre/post field 与 predictor，共四个真实场；在计算节点打开 payload，用旧 canonical 指纹与 native layout 核验。通过当前 L1 工厂的新 R8 public stage 调用重建响应，完整 stage 与原捕获 exact；不注入旧 capability 或旧 response。A 为原强度链；B 为含未变 max/FFT/IFFT/sum 的完整 Eq10 局部链。C 无实数组，记 UNAVAILABLE。

290714 原始元数据已由主线程恢复，本轮只读使用。其技术探针仍未过干扰门、正式样本为零，不能作为 GPU 原生分段秒数。本轮不启动 GPU。

## 对照、时钟及判别

以 PLAN.json 为机器可读固定表。第一轮 REF、P1、P8、P24、P48，每配置两次热身、五次正式，第二区组顺序相反。两个区组不是两个独立节点。

P_LOCAL 固定块长 16384 元素，24 线程必测；只有同链、同输入的 P48/P24 中位比在两个区组都不大于0.97时，才测 P_LOCAL48。P/P_LOCAL 同线程重新成对测试，不把不同轮混为配对。

先对四个真实输入的全部 P/P_LOCAL 配置 exact，再开始性能。完整局部调用计入输入检查、输出分配、线程任务/标量记录、barrier/join、原 FFT 与归约。线程池启动单列；如后续接入传播，计入完整应用。输出身份、psutil/NUMA快照在时钟外统一采集；其对缓存的影响属于此次孤立回放环境，不冒充原全窗画像。

P1控制揭示改写表达式、显式 out 分配与线程管理的成本；不预设它与 REF 相等，也不把其变化全归为线程因素。P与P_LOCAL使用同样ufunc、操作舍入次序和输出布局。现有数组/标量exact规则不变，NaN科学字段仍拒绝。

候选要求：所有真实输入 exact，两个顺序区组完整调用中位均至少改善5%；按保守估计的当前CPU绝对收益选一条。A的旧锚为12.528秒，B完整Eq10为34.388秒（其中FFT约8.610秒保持原样）；首个pre/post不能代表全8区间，投影只作排序假设，最终由小网格同期全路径验证。

## 资源与停止条件

最多两个新CPU JobID，每个单节点96物理核、30分钟、64GiB；累计96核时。GPU为零。实际可用内存80%guardian，进程1680秒停止以留归档时间。

实数组N=40,569,984，每个float64场约0.302GiB、complex128约0.605GiB。保留四份E/I/响应共约4.84GiB；逐份旧stage、fresh stage和完整FFT/ufunc工作区按额外12GiB预留；比较器/解压/JIT/线程与库再预留至24GiB总峰值。该估算低于64GiB的80%即51.2GiB；实际cgroup更紧则按实际门停止，不扩内存。

第一allocation完成机制矩阵；第二allocation仅可用于明确工程故障修复，或本计划已登记的单一赢家小网格接入。这样避免在尚未判别机制前接入多个候选。若无赢家，禁止再用第二作业加样本择优。

条件接入固定[384,117,129]：先真实2区间exact，再8区间同期L1/单候选对照。原112首边界、终态/Qacc/POST/布局/alias/寿命不变；采用旧完整body第2–8区间中位至少3%、方向一致和应用护栏。小网格门不达标即停止。原尺寸完整传播不在授权内。

所有控制、时间、输出身份、失败记录保留；无实际硬件计数器就不宣称DRAM、NUMA、GIL或缓存瓶颈已确诊。有效负结果也构成交付。

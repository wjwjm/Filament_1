## 2. What E5-0 established：设计与准备成果

**架构：** `architecture_choice=USER_FIXED_EXISTING_STREAMING`，
`intra_pulse_optical_hydro_overlap=REQUIRED`，`production_hr4c_replacement=false`。
Streaming CURRENT/POST/NEXT继续作为生产权威路径，保留逐screen POST、queue、claim、hydro worker、barrier和promotion。
同一发内 optical–hydro overlap保留；下一发只能在前一发完整barrier/promotion后开始。
HR4C只作隔离Batch/reference对照。旧HR4C-authoritative生产方案和full-POST-before-hydro顺序均为
**SUPERSEDED / NOT CURRENT PLAN**，不再进入实施路线。

**跨发：** 已闭合每发fresh optical field、读取本发CURRENT/PRE、PRE→POST→NEXT、
前发已promotion的NEXT→下一发CURRENT、独立lifecycle root、lineage/ready receipt/pulse index/restart epoch、
跨allocation恢复、中途optical replay与durable POST复用，以及末发POST_final专用闭合。
末发不执行额外hydro/NEXT。所有新增跨发合同为 **DESIGNED / NOT_IMPLEMENTED**，不是运行通过。

**PRE0：** frozen E1B delta_n的连续前缀，加 deterministic float64零vx/vy，是工程验证初态；
不声明其对应自然脉冲列的完整物理历史。原整数组hash不充当派生前缀hash，
派生文件物化后的hash仍须future preflight产生并绑定。

**E5-1候选：** Npulses=3、K=8048、source indices=0..8047、z约0..0.8048m
（原schedule精确终点0.8047999999999277m）、block_size=8、1006个完整block。
这是engineering canary，不冻结E5-2/formal科学终点。原48-screen qualification不是传播域。
直接使用原始连续schedule slice，不重新build缩短z_max而引入新浮点步长；full-z仍可另审，非当前推荐。

**Exact/evidence：** serial/Batch reference与Streaming candidate使用相同input/PRE0/schedule/config/LUT；
逐发PRE/POST、仅非末发NEXT、deposition、ledger与final optical保留逐数组exact比较。
科学exact与调度/恢复provenance分层验收；每个非末发验证 `hydro_start < optical_complete`。
不把物理趋势幅度设为engineering PASS门。

**资源：** 已确定需求预算，而非验证资源可用。保守双轨保留科学payload为669,587,300,928 bytes
（623.601769 GiB），recommended available/quota为851,693,145,010 bytes（793.201053 GiB）。
历史filesystem free-space约180GiB既不支持本方案，也不是verified user/project quota。
QoS数值限制、quota、retention/purge、GPU model/VRAM/CUDA、实测RSS/VRAM/I/O仍待核实；
大规模manifest累计I/O须后续小型metadata preflight/profiling确认。
这些属于implementation/resource authorization门，**不是E5-0未完成项**。
